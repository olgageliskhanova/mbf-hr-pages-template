# HR-страницы MBF — правила для Claude

## Кто со мной работает
Наталья, HR MindBodyFace. Не программист, работает только в браузере (claude.ai/code), с разных компьютеров.
- Пиши по-русски, коротко и просто, без терминов. Термин нужен — объясни в 5 словах.
- Одно действие за раз: «нажми X», «открой Y». Жди ответа, потом следующий шаг.
- Всё, что можно сделать в репозитории, делай сам. Наталью проси только о том, что требует её браузера: GitHub, Google-таблица, проверка живой страницы.

## Адрес сайта
`ВПИСАТЬ_ПРИ_ПЕРВОЙ_СЕССИИ` — спроси у Натальи адрес из Vercel (вида `https://….vercel.app`) и впиши сюда.
Страница из папки `site/<имя>/` открывается по адресу `<адрес сайта>/<имя>/`.

## Что собираем
HR-страницы: тест, аттестация, анкета, опрос, программа адаптации или обучения.
Сотрудник проходит страницу по ссылке → ответы падают строкой в Google-таблицу HR.

```
site/<имя>/index.html ──▶ site/api/submit.js (сервер Vercel) ──▶ Apps Script в таблице ──▶ строка в листе «Ответы»
```
Репозиторий подключён к Vercel (Root Directory = `site`). Слияние в `main` → Vercel сам выкладывает сайт за 1–2 минуты.

## ⛔ Так не делать (проверено на аттестации 18.08.2026)
- Артефакт claude.ai не итог. Сотрудник без аккаунта Claude не сохранит прогресс, а ответы оттуда в таблицу не уйдут.
- Не отправлять ответы со страницы прямо на Apps Script (`mode: 'no-cors'`): ошибки не видны, ответы теряются молча. Только через `/api/submit`.
- Адрес Apps Script (`/exec`) и ссылки на таблицу в коде страницы не писать. Адреса живут только в `site/api/submit.js`.
- Google Forms не предлагать: дизайн не настраивается.
- Не трогать чужие страницы в `site/`, если Наталья не просила.
- Не пушить в `main` напрямую. Работать в своей ветке; в `main` попадает только через pull request, который сливает Наталья. Бесплатный Vercel выкладывает сайт от её имени, коммиты от имени Claude он может не пропустить.

## Где что лежит
- `site/` — то, что выкладывается в интернет. Только страницы, `api/submit.js`, `vercel.json`, `index.html`-заглушка.
- `site/<имя>/index.html` — одна страница = одна папка. Имя латиницей через дефис (`attestation-dec`).
- `site/api/submit.js` — словарь `SHEETS`: имя папки → адрес таблицы. Одна строка на страницу.
- `templates/apps-script.gs` — код, который Наталья вставляет в таблицу.
- `templates/send.js` — как страница отправляет ответы.
- `inbox/` — ТЗ, если Наталья загрузила его в репозиторий.

## Порядок работы над новой страницей
1. **ТЗ.** Возьми ТЗ из сообщения или из `inbox/`. Перескажи в 3–5 строках: что за страница, сколько вопросов, именная или анонимная, нужен ли подсчёт баллов. Неясно — спроси.
2. **Сборка.** Создай `site/<имя>/index.html`. Один файл, всё внутри (стили, скрипт). В `SHEETS` добавь строку `'<имя>': 'ВСТАВИТЬ_АДРЕС',`. Требования к странице:
   - `<!doctype html>`, `<meta charset="utf-8">`, `<meta name="viewport" …>`, `<meta name="robots" content="noindex">`;
   - на телефоне 390 px без горизонтальной прокрутки;
   - обязательные вопросы подсвечиваются, если не заполнены;
   - у вариантов «Другое» есть поле для своего ответа;
   - ответы до отправки хранятся в `sessionStorage`, при ошибке кнопка «Отправить ещё раз»;
   - пока таблица не подключена (`GET /api/submit?form=<имя>` → `ready: false`), сверху плашка «режим проверки»;
   - `FORM` = имя папки; `headers` — тексты вопросов, `values` — ответы в том же порядке (см. `templates/send.js`).
   Перед отправкой: `node --check site/api/submit.js`.
3. **Выложить черновик.** Закоммить и запушь в свою ветку. Затем веди Наталью: в окне Claude нажать **Create PR** (не «Create draft PR»: черновик слить нельзя), на GitHub открыть этот pull request → **Merge pull request → Confirm merge**. Через 1–2 минуты страница откроется по `<адрес сайта>/<имя>/` с плашкой «режим проверки». Ссылку пока никому не отправлять. Правки — тем же путём.
4. **Таблица.** Попроси Наталью создать пустую Google-таблицу в её HR-аккаунте и поставить код из `templates/apps-script.gs` (для анонимной анкеты сначала поменяй в нём `ANONYMOUS = true` и дай ей готовый текст). Шаги — раздел «Apps Script» ниже, по одному. Она присылает адрес на `/exec`.
5. **Подключить.** Впиши адрес в `SHEETS` вместо `ВСТАВИТЬ_АДРЕС`, закоммить, запушь, снова веди Наталью через pull request и Merge.
6. **Проверка.** Наталья открывает страницу (плашки «режим проверки» нет) и отправляет ответ с именем «ТЕСТ Тестов». В таблице строка 2 — удалить её. Строку 1 с вопросами не трогать.
7. **Готово.** Ссылку на страницу можно рассылать. Ссылку на таблицу сотрудникам не давать.

## Apps Script (делает Наталья, ~10 минут на таблицу)
1. В таблице: **Расширения → Apps Script**.
2. Удалить всё в редакторе, вставить код, **Сохранить** (💾 или Ctrl+S / Cmd+S).
3. Справа сверху **Начать развертывание → Новое развертывание**.
4. ⚙ рядом с «Выберите тип» → **Веб-приложение**.
5. **Запуск от имени: Я**. **У кого есть доступ: Все**. Не «Все, у кого есть аккаунт Google», иначе сайт не сможет писать.
6. **Начать развертывание → Предоставить доступ** → свой аккаунт. Google предупредит, что приложение не проверено: **Дополнительные настройки → Перейти на страницу … (небезопасно) → Разрешить**. Это нормально: скрипт её собственный.
7. Скопировать **URL веб-приложения** (оканчивается на `/exec`) и прислать в чат.
Проверка: адрес, открытый в браузере, показывает `{"ok":true,"sheet":"<название таблицы>"}`.
Поменяли код скрипта → **Начать развертывание → Управление развертываниями → ✏ → Версия: Новая версия → Начать развертывание**. Адрес не меняется.

## Если не отправилось
Страница показывает причину мелким серым текстом.
| Текст | Что значит | Что делать |
|---|---|---|
| адрес таблицы не вставлен | шаг 5 не сделан или не слит в `main` | вписать адрес, pull request, Merge |
| header mismatch | в таблице добавили/удалили колонку или поменяли вопросы | вернуть строку 1 или завести новый лист |
| HTTP 401 / 403 / кусок `<html` | доступ не «Все» или адрес не от веб-приложения | Управление развертываниями → доступ «Все»; адрес на `/exec` |
| нет связи / нет ответа | интернет у сотрудника | «Отправить ещё раз» |
Страница не обновилась после Merge → попроси Наталью открыть Vercel → проект → Deployments и прочитать статус последней выкладки.
Красная отметка Vercel на pull request (Preview для ветки Claude) — не страшно: сайт выкладывается из `main` после Merge.
Доступа в интернет к `*.vercel.app` и `script.google.com` у тебя нет: живую страницу и таблицу проверяет Наталья.

## Правила для HR-данных
- Анонимная анкета: без имени, `ANONYMOUS = true` (только дата, без времени), иначе человека вычислят по времени.
- Тест с правильными ответами: ответы в коде страницы видит любой. Для аттестации с последствиями проверку баллов делай на сервере в `site/api/` и скажи об этом Наталье.
- Поменялись вопросы после запуска — новая таблица или новый лист. Иначе ответы съедут в чужие колонки.
- Ответы сотрудников в репозиторий не класть и в другие сервисы не отправлять.
